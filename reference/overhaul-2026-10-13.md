# Reference — Overhaul record, 2026-10-13

On 2026-10-13 the operator authorized a complete overhaul of how this deployment operates ("You have
full permission to completely overhaul cadre") and the supervisor was issued directives O1–O6 below.
This file is the record: the evidence that forced it, the directives, and where each one is codified.
The standing boundary is unchanged by the overhaul: credentials, spending, external publishing, and
actions on the operator's real accounts still stop at the operator.

---

## The evidence — three runs, one day, one team

Same roster, same game (*Return to Eden*), same day. Only the operating regime changed.

| Run | Regime | Result |
|---|---|---|
| 60 min | Default — supervisor reconciles the board, works queue priorities | **0 game artifacts.** The hour went to reconciling task state (one task's "current" report was 13 checkpoints stale). |
| 45 min | Operator decisions issued, then hands-off | **0 game artifacts.** The window went to task selection, claims, and hash verification; the runtime never started. |
| ~2 h window | Restructured + micromanaged — one named owner, a deliverable stated as something a player can see, operator check-ins every ~15 min | **Battle 1 played end-to-end.** Full screenshot evidence set (menu, deployment, mid-battle, end screen) with hashes — first complete evidence ~44 min after dispatch. |

Failure modes the day exposed:

- **Ceremony capture.** Claims, checkpoint numbering, reconciliation, and hash ledgers consumed
  entire run windows while producing nothing a player could see.
- **A self-referential task graph.** The board was dominated by pipeline-about-pipeline tasks;
  "game work" selected from it was more pipeline.
- **Evidence inflation.** A producer reported a complete four-screenshot bundle; reconciliation
  found one file was a byte-identical alias of an earlier capture and one stage had never been
  reached. Caught — but only by an expensive reconciliation pass.
- **Authority ambiguity.** Delegated decisions were re-asked of the human agent by agent, and one
  lane tried to recall the run's owner mid-run pending personal confirmation.
- **Supervisor fragility.** A supervisor run failed mid-relay; a record kept only in that run would
  have been lost with it.
- **Timers on stalled tasks.** Automatic check-ins fired checkpoints on blocked tasks — spend
  narrating stillness.

## The directives

- **O1. Board reset.** The v1 board is rebuilt as a short list of player-visible milestones. The
  pipeline-task backlog is archived out of the active queue (parked, not deleted); nothing re-enters
  without a player-visible statement.
- **O2. Slim game lane.** For game work the active cast is builder (build/play), QA (asynchronous
  verification), supervisor (light coordination + record). All other seats are paused for the lane
  unless a milestone names them. Codified in [`agents.md`](./agents.md) — seats activate per outcome.
- **O3. Ceremony cap.** One claim per task, one evidence ledger written once by the producer, no
  checkpoint numbering for run artifacts, no reconciliation pass unless a concrete discrepancy is
  found. Producer artifact claims are spot-verified before being reported as complete. Codified in
  [`verification.md`](./verification.md) §7.
- **O4. Escalate to the operator, not the human.** Decisions already delegated to the operator are
  not re-confirmed with the human agent by agent; scope/process questions route to the operator and
  the human receives summaries. Codified in [`collaboration.md`](./collaboration.md) §8.3.
- **O5. Internal timer audit.** Automatic check-in/dispatch timers are listed; any timer that fires
  on a parked or blocked task is disabled. No timer may generate checkpoints on a task with no
  active run window. Codified in [`scheduled-work.md`](./scheduled-work.md).
- **O6. Supervisor resilience.** Run records are written to the board as they happen, not relayed in
  one end-of-run turn, so a failed supervisor run loses nothing. Codified in
  [`agents.md`](./agents.md).

## Standing rules carried in

From the same day's operator decisions, now part of the reference set:

- **Game-first.** The game board outranks all infrastructure/meta work; no infra task blocks or
  outranks a game task.
- **Proportionate security.** Formal sign-off only for credentials, external publishing, spending,
  or the operator's real accounts; internal evidence uses dual verification instead of attestation
  proofs. [`guardrails.md`](./guardrails.md) §7.
- **Gate escalation.** A task blocked at the same gate through 2 checkpoints escalates as a decision
  (accept risk / descope / kill). [`guardrails.md`](./guardrails.md) §8.
- **Single owner end-to-end; artifact-or-blocker checkpoints; player-visible deliverables only.**
  [`collaboration.md`](./collaboration.md) §8.
